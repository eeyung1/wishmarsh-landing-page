# Wishmarsh — Landing Page

> **Share wishes. Create memories.**
> A production-ready, responsive landing page for Wishmarsh — a service for collecting
> wishes, messages and optional gifts for the people you care about.

---

## 📁 Project structure

```
wishmarsh-landing-page/
├── index.html            # Semantic HTML5 markup for every section
├── styles.css            # Design tokens, components, responsive rules
├── main.ts               # UI layer: rendering, icons, interactions
├── api.ts                # Typed API service layer + mock fallbacks
├── main.js               # Compiled bundle (generated by `npm run build`)
├── images/
│   ├── girl.jpg          # Hero visual
│   ├── guy.jpg           # "How it works" visual
│   └── boy.jpg           # Original source image for the guy photo
├── scripts/
│   ├── serve.mjs         # Zero-dependency static preview server
│   ├── shot.mjs          # Headless-Chrome screenshot helper
│   ├── check.mjs         # Smoke test for the interactive flows
│   ├── overflow.mjs      # Reports elements that overflow the viewport
│   └── imgstate.mjs      # Reports image loading state
├── package.json
└── tsconfig.json
```

## 🚀 Getting started

```bash
npm install          # install typescript + esbuild (dev dependencies)
npm run build        # type-check and bundle main.ts -> main.js
npm run serve        # preview at http://localhost:4173
npm run dev          # build + serve in one go
```

Other scripts:

| Script | Purpose |
| :--- | :--- |
| `npm run typecheck` | Strict TypeScript check (no emit) |
| `npm run bundle` | Bundle `main.ts` → `main.js` (IIFE, ES2019) |
| `npm run build:min` | Minified production bundle |
| `npm run watch` | Rebuild on change |
| `npm run clean` | Remove build output |

> `index.html` ships with a pre-built `main.js`, so the page also works when opened
> directly from the filesystem (no server, no build step required).

## 🎨 Design system

All tokens live at the top of `styles.css` under `:root`.

| Token | Value | Usage |
| :--- | :--- | :--- |
| `--brand-dark-wine` | `#4A0515` | Hero background, active button text |
| `--brand-wine-gradient` | `linear-gradient(135deg, #60081D 0%, #3B0310 100%)` | Header / hero backdrop |
| `--brand-button-accent` | `#6F0A23` | Primary CTA, icon strokes |
| `--brand-cream-bg` | `#FFF9FA` | Wish wall section background |
| `--pure-white` | `#FFFFFF` | Cards, buttons |
| `--text-primary` | `#1F1F1F` | Headings |
| `--text-muted` | `#666666` | Body copy |
| `--border-subtle` | `#F1E4E7` | Card borders |

* **Type** — `Plus Jakarta Sans` (UI) and `Caveat` (handwriting / sticky notes), with
  system fallbacks so nothing breaks when the webfont is unavailable.
* **Radii** — pill (`9999px`) for buttons and badges, `16px`–`24px` for cards.
* **Icons** — every icon, logo, doodle and avatar is an **inline SVG**. There are no
  icon fonts, sprite sheets or third-party icon dependencies.

### Image integration

* `images/girl.jpg` and `images/guy.jpg` are masked with organic `border-radius` shapes
  and layered over CSS wine backdrops (`::before`-style sibling elements) so they read as
  cutouts whether the source is a raw photo or a transparent PNG.
* White line-doodles (hearts, burst lines, sparkles, squiggles) are inline SVGs positioned
  absolutely around each photo.
* Both images declare explicit `width`/`height` plus `object-fit: cover`, and the
  below-the-fold image uses `loading="lazy"` — so there is no Cumulative Layout Shift.

## 🔌 API integration

`api.ts` exposes a fully typed `WishmarshApi` service. Every call degrades gracefully to
bundled mock data, so the page works standalone.

| Method | Route | Purpose |
| :--- | :--- | :--- |
| `POST` | `/api/events` | Initialise the event creation flow (CTA buttons) |
| `GET` | `/api/categories` | Event category list |
| `GET` | `/api/wishes/sample` | Sample cards for the collage wish wall |
| `POST` | `/api/auth/login` | Authentication entry point |
| `POST` | `/api/auth/register` | User registration entry point |

```ts
import { WishmarshApi } from "./api";

const { data, isFallback } = await WishmarshApi.getCategories();
const event = await WishmarshApi.createEvent({ source: "hero", categorySlug: "birthdays" });
```

Point the client at a different environment with `API_BASE_URL` or
`WishmarshApi.setBaseUrl("https://api.wishmarsh.app/api")`. Requests time out after 6 s and
fall back to `MOCK_CATEGORIES` / `MOCK_WISHES`.

### TypeScript models

`Category`, `Step` and `WishWallNote` (UI models) live in `main.ts`; `EventCategory`,
`WishNote`, `CreateEventPayload`, `CreateEventResponse`, `AuthPayload` and `AuthResponse`
(DTOs) live in `api.ts`. The compiler runs with `strict`, `noUncheckedIndexedAccess`,
`exactOptionalPropertyTypes` and `noUnusedLocals` enabled.

## ♿ Accessibility

* Semantic landmarks (`header`, `nav`, `main`, `section`, `footer`) and a skip link.
* The auth dialog is a proper `role="dialog"` with `aria-modal`, focus trapping,
  `Escape` to close and focus restoration.
* Visible `:focus-visible` rings, `aria-live` toast and labelled icon-only controls.
* `prefers-reduced-motion` disables the reveal and float animations.

## ✅ Quality checks

```bash
npm run typecheck                     # strict TS
node scripts/check.mjs                # headless smoke test (nav, modal, CTA, reveal)
node scripts/overflow.mjs 390 844     # horizontal overflow report
```

`scripts/check.mjs` asserts that all six categories, four steps, three sticky notes and
two polaroids render, that the modal opens and submits, that the CTA restores its label,
that the mobile drawer toggles, and that the document has no horizontal overflow.
